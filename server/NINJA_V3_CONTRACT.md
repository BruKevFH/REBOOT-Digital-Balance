## Service and storage

Keep existing `server/ninja-leaderboard.mjs` and its production Render deployment as clearly legacy/unverified; do not silently mix its rows into verified scores. No paid plan/disk may be activated. Report external persistent hosting as blocked until provisioned. Existing Render Free `/tmp` storage is not acceptable for verified accounts.

`server/ninja-store.mjs` exports `createNinjaStore({databasePath,now})`: `{db,transaction(fn),close,getProfile(userId),putProfile(userId,profile),...}`. DatabaseSync is synchronous; transaction callbacks are synchronous and use BEGIN IMMEDIATE/COMMIT/ROLLBACK. Never await inside a transaction. Enable foreign keys/WAL/busy_timeout and migrations. `users`: id, username, normalized unique username_key, password_hash, recovery_hash, created_at. `sessions`: token_hash, user_id FK cascade, expires_at. `profiles`: user_id FK PK, data JSON, revision, run_sequence. `wallets`: user_id FK PK, balance integer CHECK(balance>=0). Profile getter overlays authoritative wallet balance and current username; all values remain owned by authenticated user. Wallet changes are managed by game-service inside the same transaction as profile/ledger updates.

Auth module `server/ninja-auth.mjs` exports `createNinjaAuth(store,{now,sessionTTL,...})`, methods async register({username,password}), login({username,password}), authenticate(token), logout(token), resetPassword({username,recoveryKey,password}), deleteAccount(userId,{password}), rename(userId,username). Registration/login return `{user:{id,username},token,expiresAt,profile,revision}`; register/reset also return a new one-time recoveryKey (shown only once). No email needed; pseudonym/password plus recovery key avoids an invented SMTP dependency. Password uses built-in crypto.scrypt with random salt and documented parameters; session and recovery secrets use randomBytes and SHA256 hashes at rest. Password 10–128 characters chosen default; username uses existing validateUsername. Neutral login/reset errors. Root router owns request/IP rate limits, CORS and static serving. Auth must revoke all sessions on reset/delete, and session on logout.

## API contract (root router `server/ninja-service.mjs`)

Root API prefix `/api/v3`. The implemented session model uses explicit Bearer opaque tokens only; it neither issues nor accepts auth cookies. Browser requests omit credentials, so a cross-site cookie cannot implicitly authenticate a mutation. Frontend stores only session token in sessionStorage for cross-origin use, never a password or auth token in localStorage. Endpoint body limits: small account/action requests <=32KB; run logs <=2MB, bounded commands. No tokens/passwords in logs.

- GET /health: service readiness, durableStorage, apiVersion:3, no secrets/paths.
- POST /auth/register, /auth/login, /auth/reset; POST /auth/logout; GET /me.
- PATCH /profile: validated username; DELETE /account: password confirmation.
- POST /actions: `{type,id?,payload?,idempotencyKey}`; returns authoritative `{profile,revision,...}`.
- POST /runs/start: `{kind:'quick'|'mission'|'normal',context?,mode?,missionId?,difficulty?,gamingLimit?,viewport:{width,height}}`; returns `{runId,seed,startedAt,expiresAt,initial:game.exportData(),ruleset}`.
- POST /runs/:runId/finish: `{commands}`; server replays, derives all scores/progress/rewards, once only. Returns `{profile,revision,run:{id,result,score,decisions,duration,verified,published:false,...}}`.
- POST /runs/:runId/publish: explicit consent, only finished verified Open/lives/open-v2, idempotent.
- GET /leaderboard?ruleset=open-v2&limit=25: only verified+published rows, best/user, rank/username/score/duration/decisions/submittedAt; no private IDs. Own position may be returned for authenticated user.

Legacy public leaderboard stays a separately labelled historical service. New account API is locally functional even if external durable hosting cannot be activated. `accounts-config.json` on static GitHub Pages can default disabled; integrated service overrides this route with enabled same-origin API configuration. Frontend must give a clear retry/guest fallback, never fake an online account.

## Game service and verification

`server/ninja-game-service.mjs` exports `createNinjaGameService(store,{now,maxCommands,...})` with getState(userId), action(userId,body), startRun(userId,body), finishRun(userId,runId,body), publishRun(userId,runId), leaderboard(userId|null,query). It owns ledger, idempotency, run, verified-score tables/migrations and transactions. Use existing game/progression rules on authoritative server profile. Never import arbitrary client coins/XP/unlocks. Guest import carries only tutorial acknowledgement and safe preferences once; local guest progress stays intact and unverified. No merging or adding local balances. Settings schema is bounded. Return existing model profile shape plus revision.

Server run is seeded, user-bound and stores initial export snapshot/viewport/ruleset/profile revision. Frontend uses exactly that initial model snapshot. Commands are arrays `[method,args]`, only public simulation methods: update, swipe, resize, nextLevel, setPaused, pause, resume, resumeRun, requestStop, continueAfterLimit, continueSleep, activateSuper, finishRound, skipTutorial. Do not log/publish arbitrary property writes or profile actions. update dt is finite 0..0.05; resize 240..5000; swipes bounded 256 points/finite coordinates. Limit total commands, total active duration, request size and wall-clock duration (`active <= now-startedAt + small tolerance`). Require an actual ended result; replay derives points and metrics. Reject unknown methods, forged run ownership, duplicate differing finish data, impossible elapsed time or manipulated scores. No claim of perfect anti-cheat. Resume trace persists only in the account's session/cache namespace; network interruption queues validation, never gives spendable unverified account coins. Expired/invalid runs can remain local practice results.

Run finish must merge deltas into latest profile transactionally; do not overwrite purchases/claims made while a run was paused. Keep skill/super/run loadout frozen at start. Wallet ledger debit/credit, ownership and progress update atomically, idempotency user-scoped. Actions map to existing model methods: skin.buy/equip, world.buy, background.buy/equip, skill.buy, super.equip, achievement.claim, daily.claim, career.claim, weekly.claim, weekly.skin, notification.read, notifications.read, guide.seen, settings.update, guest.import. Purchase requires explicit UI confirmation. Server checks all costs/prerequisites/owned state. Concurrency tests need independent same-user requests.
